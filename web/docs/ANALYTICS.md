# Аналитика lab-career.ru

Что и в каких разрезах меряем, где это лежит и где смотреть.
Фазы 0-4 реализованы 2026-08-30, фазы 5-6 - список того, чего ещё нет.

## 1. Зачем свой контур, если есть Метрика

Метрика (счётчик 108774421, `components/YandexMetrika.tsx`) отвечает на вопрос
«сколько людей и откуда». Она не отвечает на вопросы в терминах платформы:
какое направление тянет отклики, какой кластер статей ведёт к вакансиям, где
рвётся воронка. Для этого нужен джойн событий с `vacancies` и `articles`, а
данных Метрики в нашей БД нет.

Разделение: **Метрика - источник правды по трафику и поведению, своя таблица -
по продуктовым разрезам.** Цифры не сойдутся никогда (боты, блокировщики,
разные определения визита), и это нормально: в дашборде так и написано.

Согласие: баннер остаётся информационным, opt-in не вводим. В июле 2026 счётчик
уже заворачивали в согласие - измеряемость упала с 95 % до 25 %.

## 2. Единый справочник направлений

`lib/taxonomy/directions.ts` - единственное место, где живёт канон. До него
направление называлось тремя способами: `vacancies.sphere` (13 ключей),
`user_profiles.direction` (7 русских меток), ключи калькулятора ЗП (13 своих).

Канон: 14 направлений (13 sphere + **qa отдельным**). QA, DevOps и
безопасность в вакансиях спрятаны внутри `sphere='it'`, поэтому для этой сферы
направление уточняется по названию и стеку (`directionFromVacancy`).
Аналитические роли (analyst, dataeng, sysanalyst, bizanalyst) сводятся в
`analytics`: на этой платформе это один сегмент спроса.

Мапперы: `directionFromSphere`, `directionFromProfile`, `directionFromSalaryKey`,
`directionFromSearchQuery`. Уровни: `levelFromExp`, `levelFromProfile`.

Отчёты считают направление в TypeScript, а не в SQL - чтобы копий правил не
было. Исключение: `scripts/sql/directions-report.sql` для ad-hoc запуска из
psql, там правила продублированы, и при правке канона его надо править тоже.

## 3. Словарь метрик

| Метрика | Определение |
|---------|-------------|
| Визит | сессия `cl_sid`, разрыв 30 минут неактивности |
| Посетитель | `cl_aid` (first-party cookie, 12 месяцев) |
| Просмотр вакансии | `vacancy_view`, дедуп на клиенте через sessionStorage |
| Отклик | `vacancy_apply_click` (внешний) и `application_submit` (внутренний) считаются **раздельно**, суммарная цифра не выводится |
| Регистрация | новая строка `careerlab_accounts` (не событие: событие может не долететь) |
| Дочитывание статьи | 75 % прокрутки И не меньше 30 секунд на странице |
| Лид B2B | клик по CTA пакета на `/for-companies` |

## 4. Разрезы

Общие: время (7/30/90 дней), направление, уровень, тип страницы, кластер
статьи, канал (organic / telegram / social / referral / direct / paid / email),
устройство, город, гость или залогинен.

По сущностям: вакансия, статья, компания, вуз, инструмент.

## 5. Событийная модель

Имена событий - в `KNOWN_EVENTS` (`lib/analytics/events.ts`); неизвестные имена
отбрасываются на записи.

| Событие | Где ставится |
|---------|--------------|
| `page_view` | `components/AnalyticsTracker.tsx` в корневом layout, на каждую смену маршрута |
| `vacancy_view`, `vacancy_apply_click`, `vacancy_save` | `components/vacancies/VacancyDetailClient.tsx` |
| `article_view`, `article_read` | `components/analytics/ArticleReadTracker.tsx` |
| `tool_start`, `tool_finish` | `components/office/InlineResumeAnalyzer.tsx`, `components/tools/SalaryCalculatorPage.tsx` |
| `register_start`, `register_success` | `components/LoginForm.tsx`; для Яндекс OAuth - серверное событие в `app/auth/callback/route.ts` (новый аккаунт определяется по `xmax = 0`) |
| `profile_completed` | `components/office/OfficeDashboard.tsx` |
| `application_submit` | `components/vacancies/ApplyForm.tsx` |
| `company_lead_click` | `components/PlacementRequestForm.tsx` (`stage: open` и `stage: sent`) |
| `tg_click` | `components/TgStickyBar.tsx` |
| `search_performed` | отдельного события нет: поиск уже пишется в `search_queries` |

Каждое событие, кроме `page_view`, автоматически дублируется **одноимённой
целью Метрики** (`track()` зовёт `ymGoal()`). Чтобы цели заработали, их надо
один раз завести в интерфейсе Метрики с этими же именами - код ничего для
этого не требует.

## 6. Как это устроено технически

- **Идентификаторы** ставит middleware (`lib/analytics/middleware-identity.ts`):
  `cl_aid` на 12 месяцев и `cl_sid` на 30 минут с продлением. Не из JS - так
  они переживают блокировщики. Ботам куки не выдаются.
- **Клиент** (`lib/client/track.ts`) копит события и шлёт батчем до 20 штук
  через `sendBeacon`: по таймеру 2 с, при уходе со страницы и при скрытии вкладки.
- **Приём** - `POST /api/track`: фильтр ботов по User-Agent, rate-limit
  60 запросов в минуту на `cl_aid`, всегда 204, запись через `after()`.
  Канал, устройство и `account_id` считаются на сервере: клиенту тут не верим.
- **Хранение** - `analytics_events` (сырьё, 90 дней) и `analytics_daily`
  (суточные агрегаты, бессрочно). Отчёты дашборда читают сырьё: периоды до
  90 дней при нынешних объёмах это единицы сотен тысяч строк. Агрегаты нужны,
  чтобы история не пропадала после чистки.
- **Приватность**: IP не пишем вообще, `cl_aid` не связан с личностью до
  логина. Кабинеты компаний и вузов и админка не трекаются.

Не трекаются пути `/company*`, `/vuz*`, `/admin*`, `/api*`, `/auth*`
(`lib/analytics/page-type.ts`). Личный кабинет студента `/office*` трекается -
это середина воронки.

## 7. Где смотреть

`stats.lab-career.ru` (он же `/admin/analytics`), доступ - только аккаунты из
`PLATFORM_ADMIN_EMAILS`, весь раздел noindex. Поддомен - это тот же процесс
Next: middleware переписывает пути, отдельного деплоя и второй авторизации нет
(nginx-конфиг и DNS - в DEPLOY.md).

Вкладки:

1. **Обзор** - KPI с дельтой к прошлому периоду, визиты по дням, воронка,
   каналы, типы страниц.
2. **Направления** - спрос против предложения: доля вакансий против доли
   просмотров, разрыв в процентных пунктах, CTR, сохранения, поисковые
   запросы и нулевая выдача, профили. Ниже - запросы, которые словарь
   направлений не узнал: готовый список правил, которые стоит добавить.
3. **Вакансии** - что именно смотрят: тип занятости, опыт, формат, зарплата
   (указана или скрыта), город, возраст вакансии, источник, компания. Плюс топ,
   «смотрят, но не откликаются» (высокие просмотры и низкий CTR) и «мёртвый
   груз» - опубликованные вакансии без единого просмотра. Разрезы получаются
   джойном событий с `vacancies` по slug, дополнительной разметки не требуют.
4. **Контент** - кластеры базы знаний, доля дочитываний, топ и аутсайдеры,
   переход «статья → вакансия» в рамках визита.
5. **Пользователи** - регистрации по месяцам и неделям, воронка активации
   (подтвердил email → заполнил профиль → сохранил вакансию → прогнал резюме →
   отправил отклик), «признаки жизни» (когда аккаунт в последний раз оставил
   след в БД - исторический суррогат удержания), когорты удержания по неделям
   регистрации (считаются по событиям, наполняются с 30 августа 2026), состав
   аудитории по анкете.
6. **Инструменты и поиск** - анализатор резюме (запуски, доводимость до
   результата, распределение баллов), калькулятор зарплат (какие направления,
   уровни и города считают - прямой индикатор спроса), поиск (нулевая выдача,
   популярные запросы, какими фильтрами пользуются и что в них выбирают).

Пока событий мало, вкладка «Направления» показывает просмотры и клики из
накопительных счётчиков `vacancy_stats` (за всё время, без отсечения ботов) и
честно пишет об этом в шапке. Как только пойдут свои события, она переключается
на них автоматически.

## 8. Что показал первый замер (30 августа 2026, до разметки)

По `vacancy_stats` + `search_queries` + `user_profiles`:

| Направление | Вакансий | % предложения | % спроса | CTR |
|-------------|---------:|--------------:|---------:|----:|
| Аналитика | 200 | 31,3 | 31,5 | 12,2 % |
| Разработка | 207 | 32,4 | 24,5 | 9,1 % |
| **Дизайн** | 28 | **4,4** | **14,3** | **31,8 %** |
| Продукт | 57 | 8,9 | 9,9 | 13,9 % |
| **Маркетинг** | 27 | **4,2** | 6,0 | **23,4 %** |
| QA | 36 | 5,6 | 5,2 | 10,0 % |

Дизайн и маркетинг - главный разрыв: доля вакансий втрое-вчетверо меньше доли
интереса, а конверсия в клик по отклику там самая высокая. Плюс у дизайна
35 % поисковых запросов уходят в нулевую выдачу (29 из 83).

## 9. Чего ещё нет

- экспорт CSV;
- недельный дайджест на почту;

## 10. Грабли

- Прод-дерево бывает грязным: перед деплоем `git status` в `/var/www/hr_platform`.
- Цели Метрики надо завести руками, иначе `reachGoal` уходит в никуда.
- Ретеншен 90 дней включён с первого дня - таблица не должна расти бесконтрольно.
- `analytics_rollup` идемпотентна и пересчитывает 3 последних дня: пропущенный
  запуск догоняется следующим.
